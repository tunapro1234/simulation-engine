# Pre-registration: Latent persona: person vectors inside open LLMs vs encoder-only and LLM-free models (GPU day), 2026-10-23

_Written and locked before any result was computed. Never edited after the lock: changes go into dated, separately locked addenda next to this file (`<name>-EK<k>`, research.add_addendum)._

## Question
If a person's survey answers and purchase history are turned into a vector and put inside an open LLM (probe readout of the LLM's own state, contrastive trait steering, a learned residual projector, soft tokens, SAE features, a QLoRA fine-tune) instead of into the prompt, does the LLM add predictive signal on top of an encoder + linear head that sees the same vector without any LLM, and on top of the LLM-free history model T3 (talp73)? And does an LLM with an injected person keep its counterfactual price response, including outside the price range it was trained on (Twin pricing)?

## Data
- All three tasks were prepared by runs/latent/veri_hazirla.py (commit 1ed3a51; byte-identical on rerun) into /data/talp/is/latent/veri/{talp73,twin,twin_fiyat}/ (README.md + ozet.json there). No data rows, person ids or answers go into this repo.
- G1 talp73 (primary): Open e-commerce 1.0, TALP uretim/talp73 PROTOKOL v1.0-v1.6.1 (V1-V8). Unit person x 20 categories, y = >= 1 item in the window. Seeds 0/1/2: test = the seed's 400 sampled persons at cut 2022-07-01, labels 2022-07..12 (panel etiket_s<s>); train = 4,337 other persons at cut 2022-01-01, labels 2022-01..06; ic_dogrulama = 867 of those train persons (klasik.py early-stopping persons, default_rng(100+s)).
- G1 inputs: kisi_ozellik (32 survey columns), kisi_metin (the L1 profile text, identical to the API LLM arms), gecmis (klasik history features, keyed by uid x cut), gecmis_metin (the L2 history block), gecmis_olay (all 1.7M line items before the cut).
- G2 twin (secondary): Twin-2K-500 (CC BY 4.0). Persona = the 171 wave 1-3 QIDs not asked again in wave 4 (kisi_ozellik, 560 columns incl. skor_* construct scores; kisi_metin.metin_demografi). Target = the 86 non-pricing wave-4 items (y01 in [0, 1]); 68 option items (MC 28 + Matrix 40) and 18 numeric items (Slider 12, TE 6). Split default_rng(0): 400 test, 1,658 train, 331 ic_dogrulama. The same items' wave 1-3 answers (gecmis) are NOT an input of any persona arm here.
- G3 twin_fiyat (counterfactual): Twin pricing study, 40 products at a randomly assigned price (11 levels, 0x to 2x the median). 10 target products (wave 4 answers), 30 history products (wave 1-3 answers at their shown price). Same person split as G2. fiyat_izgara = 10 products x 11 levels for the sweep.
- G3 extrapolation split (new, fixed here): every G3 fit, selection and calibration uses only target rows with carpan <= 1.0 (levels 0, 0.2, ..., 1.0). Rows with carpan in {1.2, ..., 2.0} are never used for fitting by any arm (LLM-free arms included); they are the out-of-support test of price response.

## Split
- Person-level, fixed by the prepared tables (column bolum, ic_dogrulama). Test persons never enter a fit, a selection or a calibration. A person can be test in one talp73 seed and train in another; tables are keyed by (uid, kesim) and seeds are never mixed.
- RULE R-HP (hyperparameters): every free choice - layer, pooling, probe estimator, PCA size, steering coefficient c, steered positions, number of soft tokens k, learning rate, epochs (early stopping), regularisation C, head type (logistic vs MLP), calibration - is chosen ONLY on the ic_dogrulama persons, with the model fitted on the remaining train persons. G1 selection score: within-person AUC on the validation persons' 2022-H1 labels (ties: 1a(a) accuracy, then the cheaper config); G2: MAD accuracy on validation persons; G3: AUC on validation rows with carpan <= 1.0. Test rows are never passed to a fit/select/calibrate function (simengine.latent.tasks.TestGuard raises). Each arm x seed writes ONE test prediction file, with the selected config. The grids under Extra are fixed now; extending a grid after any test file of that arm was scored needs a dated addendum and the arm is then exploratory.
- Learned-injector sweeps (rsd, sft) run on seed 0's validation persons with 1 epoch; the chosen config is reused for seeds 1-2, each with early stopping on its own validation persons. Probes and ENC heads are refit on all train persons (validation included) with the selected config; trained injectors keep the early-stopped weights (no refit).
- Calibration: arms that read P(yes) from a prompt (prm, caa) get a per-category Platt map fitted on the validation persons (G1; in G3 one global Platt map, so the price slope stays the LLM's). Raw P(yes) is reported as a secondary row. Arms trained with BCE (enc, prb, stk, rsd, sft) output probabilities directly.
- Swap control: for every injection arm (caa, rsd, sft) the test persons' vectors are deranged (numpy default_rng(0) derangement within the seed's test persons) and scored against the original person. Zero control: the same arm with u = 0 (rsd/sft) or c = 0 (caa).

## Metrics
- G1 primary (two co-primary measures, PROTOKOL definitions, uretim/talp73/kod/degerlendir.py unchanged): within-person AUC (interpretation 4, kisi_auc, higher is better) and 1a accuracy with decision (a) p >= 0.5 on all 8,000 rows (1a_dogruluk_a; the 'always no' constant gets 0.7637). Reported next to them: 1b(c), row AUC, Brier, precision@3.
- G1 uncertainty: degerlendir.py person-level bootstrap B = 1000, default_rng(42), paired differences against named baselines on the same resamples, 95% percentile CI, per seed. Run with TALP73_SONUC=/data/talp/is/latent/talp73/sonuc and prediction files in /data/talp/is/latent/talp73/tahmin/ (baseline files symlinked there from /data/talp/is/talp73/tahmin/; the TALP directories are not written).
- G2 primary: MAD accuracy = 1 - mean |y01_hat - y01|, averaged within person then over persons (Twin paper accuracy). Comparisons that include a prompt-readout arm are made on the 68 option items; probe/ENC arms are also reported on all 86. Secondary: within-item Pearson (mean over items).
- G3 primary (counterfactual): from the sweep (each test person x 10 target products x 11 price levels), the mean predicted P(buy) per level; s_hi = OLS slope of that curve over carpan in {1.0, 1.2, ..., 2.0}. Truth s_true_hi = the same slope of the observed test-person buy rate per level. Person-level bootstrap B = 1000, default_rng(42). Secondary: s_all over 0..2 vs the observed -0.371; AUC and within-person AUC on observed test rows, split into carpan <= 1.0 and > 1.0; demand-curve Pearson over the 11 levels.
- G1 counterfactual direction check (no ground truth exists in talp73): for every LLM arm, two extra prompt lines on the test persons - 'Prices in this category have risen by 50%.' and 'This category is on a 30% discount.' - and the mean change in P(yes) per category. Reported, not a decision rule except D5b.
- Readout health: share of next-token probability mass on the Yes/No token set (G1, G3) or on the option labels (G2); an arm whose mean mass is < 0.5 is flagged 'format failure' and not interpreted.

## Baselines
- LLM-free, existing talp73 prediction files (seen before this file): T3 = gecmis (kisi_auc 0.7276, 1a(a) 0.8066, 3-seed mean), gecmis_anket_ey (0.7268 / 0.8064), T2 = anket_ey (0.6326 / 0.7727), populerlik, sabit (1a 0.7637). API LLM rows for reference only: L1-haiku55 (0.5849 / 0.6941), L2-sonnet55 (0.7149 / 0.7899), H2cf-haiku55 (0.7279 / 0.8067).
- ENCODER-ONLY (no LLM; REQUIRED control; built here): enc-<u> = the same person vector u with a per-category L2 logistic head or an MLP head (hidden 256, category embedding 16), head type chosen on validation. u in {an: survey one-hot, gc: klasik history features of all 20 categories + implicit-ALS user factors, angc: an+gc, e5L1 / e5L2: multilingual-e5-base embedding of the L1 / L1+L2 text}. G2: enc-tw (ridge per item on kisi_ozellik) and enc-tw-e5. G3: enc-tf (logistic: product one-hot + carpan + u_tf) and lgbm-tf (LightGBM, same inputs), both fitted on carpan <= 1.0 rows.
- MATCHED encoder-only reference of an arm (fixed by information content; when two candidates exist, the one with the higher VALIDATION score is the reference, chosen before any test file is scored): survey-only arms (prm-L1, prb-L1, caa) -> best of {enc-an, enc-e5L1}; survey+history arms (prm-L2, prb-L2, sae, lora) -> best of {enc-angc, enc-e5L2}; rsd-<u>, sft-<u> -> enc-<u>; stk-<m> -> stk-e5 (LightGBM on gc + PCA of the e5L2 embedding) and T3.
- Same-model prompt persona: prm-<m>-L0/L1/L2 (persona in the prompt, P(yes) read from logits). Every injection arm is also compared with the same model's prompt arm holding the same information, prm-<m>-L1 or prm-<m>-L2 (D4: 'inside vs in the prompt').
- G2 reference rows: madde_ort 0.7621, ridge_persona 0.7765, dataset GPT-4.1-mini 0.7555, wave 1-3 retest 0.8273 (human ceiling, not a persona arm). G3: lgbm_gecmis_persona AUC 0.859 (fitted on all levels; reference only), observed slope -0.371.

## Expected result
- Honest prior, based on talp73 so far (the information is in the history; persona text adds ~+0.014 kisi_auc within the same API model):
- H1 prb-q38-L2 - matched ENC: kisi_auc difference in [-0.01, +0.01]; CI includes 0 in at least one seed (does not pass D1). prb-q38-L2 kisi_auc 0.70-0.73.
- H2 rsd-q38-angc - enc-angc: in [-0.01, +0.005]; does not pass D1. rsd - swap clearly > 0 (u carries history).
- H3 sft-q38-angc - enc-angc: same as H2.
- H4 stk-q38 - T3: in [-0.005, +0.01]; does not pass D2 in all three seeds.
- H5 G3: prm-q38-tf keeps a negative s_hi (ratio to truth 0.3-1.0); lgbm-tf is flat beyond 1.0 (|s_hi| < 0.05); enc-tf extrapolates linearly; rsd-q38-tf: no confident prior (50/50 that it passes D5).
- prm-q38-L1 kisi_auc 0.57-0.62 (below enc-an); prm-q38-L2 0.66-0.71 (below T3); caa-q38 at or below prm-q38-L1 and within 0.02 of prm-q38-L0.
- Across models: probe differences between models <= 0.01 kisi_auc; Qwen3-32B (non-hybrid) and Qwen3.8-27B (hybrid) within 0.01 on rsd. Qwen3.5-2B 0.01-0.03 below the 27-32B models on prb-L2.
- G2: prb-q38-tw - enc-tw within +-0.005 MAD; prm-q38-tw 0.74-0.77 on the 68 option items.

## Falsification
- Decision rules (applied per arm and seed; 'CI' = the paired 95% bootstrap CI of degerlendir.py or of simengine.latent.eval for G2/G3):
- D1 'the LLM adds signal': arm - matched ENC on kisi_auc has CI > 0 in all three seeds, and on 1a(a) the CI's upper bound is >= 0 in every seed (not significantly worse). Passing kisi_auc only = 'adds ranking signal'; passing 1a(a) with CI > 0 in all three seeds as well = 'adds signal' without qualifier.
- D2 'beats the LLM-free history model': arm - gecmis (T3) on kisi_auc has CI > 0 in all three seeds.
- D3 'person-specific': arm - swap_arm on kisi_auc has CI > 0 in all three seeds.
- D4 'inside is at least as good as the prompt': injection arm - prm-<m>-L1 (survey-only u) or - prm-<m>-L2 (angc / e5L2 u) on kisi_auc: CI > 0 in all seeds = better; all three CIs inside [-0.01, +0.01] = equivalent; otherwise worse/unclear.
- D5 G3 'counterfactual power kept': s_hi < 0 with bootstrap CI upper bound < 0 AND s_hi / s_true_hi in [0.5, 1.5]. D5b G1 direction: P(yes) falls under the price line and rises under the discount line in >= 18 of 20 categories (mean over test persons).
- D6 G2 'the LLM adds signal (single split)': arm - matched ENC on MAD accuracy with CI > 0 on the one split.
- Primary confirmatory hypotheses (main model Qwen3.8-27B only): H1 prb-q38-L2 (D1), H2 rsd-q38-angc (D1), H3 sft-q38-angc (D1), H4 stk-q38 (D2), H5 rsd-q38-tf (D5). Everything else - other models, caa, prm, sae, lora, G2, the exploratory X block - is secondary and reported with that label. The three-seed requirement is the multiplicity guard; the seeds' test persons overlap (996 distinct of 1,200), which makes it weaker than three independent replications; stated in the report.
- Claim A 'putting the person inside the LLM adds nothing beyond an encoder + linear head on talp73' FAILS if H1, H2 or H3 passes D1.
- Claim B 'LLM-free history models are enough on talp73' FAILS if H4 or any other arm passes D2.
- Claim C 'injection keeps the LLM's counterfactual price response' FAILS if H5 fails D5 while prm-q38-tf passes D5; if prm-q38-tf also fails D5, the counterfactual question is reported as unanswered for this model.

## Stop rule
- Seed 0 first for every G1 arm. Seeds 1-2 run only if the seed-0 point estimate of kisi_auc beats the arm's matched ENC or T3; otherwise the arm stops at seed 0 and is reported as failing D1/D2 on seed 0.
- Card order and cut-offs as in Extra 'priority'. Before any arm, a 15-minute throughput calibration on the card (prefill tok/s on 200 L2 prompts; one training step of rsd and sft); the time table is rescaled by the measured factor and items that no longer fit before 07:30 are dropped from the end of the list, never reordered after results.
- Precision: one precision per model per card for all its arms (the one that supports backward if that model has a trained arm on the card). A steering vector, probe or projector is applied in the precision it was extracted/trained in. The precision is written into every prediction file's sidecar meta.
- No API LLM calls. Only local HF models. Predictions (test files) are sealed with simengine.research.seal (registry /data/talp/is/latent/.prereg) before scoring.
- A failing readout (format failure flag) or a crash is reported as such; the arm is not re-prompted after test scores are seen.

- Hybrid-architecture risks (Qwen3.8/3.5): steering strength accumulates in the DeltaNet recurrent state; Qwen3-32B runs the same rsd arm as the non-hybrid control. Gemma-4-26B-A4B: steering may move the router; it only runs where it fits in bf16 (80 GB), because bitsandbytes does not quantise its 3-D expert tensors.
